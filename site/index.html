SOX ITGC Testing Simulation

A full-year IT General Controls test cycle for a fictional financial services company. It maps risks to controls, tests every control against full synthetic populations in Python and SQL, documents the results in audit workpapers, and ranks each exception for remediation.

    Risk and Control Matrix

    5 financial reporting risks mitigated by 9 ITGCs across user access, privileged access and change management. Click a control to see its test attribute and procedure. Download the Excel RCM.

    Exception register

    Every exception the tests found, each traceable to its source record. This is the listing that would go to control owners for remediation.

    Methodology

    Six phases, each a script in src/. Running python run_all.py regenerates everything from a fixed random seed.

    PHASE 1RCM

    Risks, likelihood × impact scoring, and 9 controls with owner, frequency, type and test attribute. phase1_build_rcm.py

    PHASE 2Synthetic data

    1,250 employees, 2.7k access grants, 185 terminations, 620 changes. Exceptions are seeded at 4–9% of the populations that were seeded, with near-miss records mixed in. phase2_generate_data.py

    PHASE 3Control tests

    Full-population tests in pandas and in SQL (SQLite with a business-day calendar), reconciled record-by-record. phase3_*.py, sql/

    PHASE 4Workpapers

    One Word workpaper per control plus a summary memo. Every number is computed from the Phase 3 results. phase4_workpapers.py

    PHASE 5Dashboard

    This page, a static PNG, and a Power BI star schema with DAX measures. phase5_dashboard.py

    PHASE 6Docs

    README with scope decisions, policy parameters and a guide to the repository.

    Check 1: pandas vs SQL

    Two independent implementations of every test must produce the same exception IDs.

    Check 2: answer key (after testing)

    The generator writes seeded exceptions to answer_key/. The tests never read it. It is compared only afterwards, to measure recall and precision.

    Traps built into the data

    The data includes records that are easy to misjudge. Revocations land on exactly the 5th business day. Friday terminations are revoked the following Monday, and business days skip NYSE holidays. Emergency changes are approved retrospectively inside the 2-day window. Normal changes are approved hours before an evening deploy on the same day. The rollback flag appears as "Y", "yes" and "Yes". Every privileged grant shows an approver on the access log, even where the approval register has no record. A test that gets any of these wrong produces false positives or misses real exceptions, and the answer-key check would show it.
